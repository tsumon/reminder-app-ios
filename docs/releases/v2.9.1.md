# iOS 2.9.1 · build 72

修复启动或返回前台时，由同步元数据变化引发的重复冲突选择。相关判定至少在 2.8.0 已存在；这不是隐藏对话框，真正的双向修改仍需选择。

- 持久化本地与远端内容基线，忽略导出时钟、计数、已知集合顺序等非内容差异。
- 合并结果必须成功上传后才标记同步成功；上传失败后保留待上传状态，重启也可重试。
- 兼容旧原始基线及漏增计数的本地内容变化；保留条件上传、备份、墓碑和历史合并。
- 不更改提醒数据库模型、账户或云端数据，不引入新服务。Android 无改动。

用户真实 WebDAV、凭据及提醒未被本次开发读取或操作。若此前一直取消真实冲突，更新后仍需明确处理；不会自动以某一端覆盖。真机通知送达、物理设备覆盖安装及用户真实同步场景尚需在原渠道验收。

## English

iOS 2.9.1/build72 fixes false repeated sync conflicts caused by metadata-only rewrites, acknowledges sync only after required uploads succeed, and persists pending uploads across restarts. Genuine conflicts still require an explicit choice. The existing unsigned IPA channel, identifiers and entitlements are retained. Android is unchanged. Real customer WebDAV data, physical-device installation upgrades and notification delivery were not exercised.
